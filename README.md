# Sentinel Control Panel

Sentinel is a security-first external Pterodactyl operations panel. It keeps the Application API key in the backend, applies role and per-server assignment decisions before every server operation, and turns configured dangerous actions into atomic Owner approvals. It deliberately does **not** fabricate console, resource, backup, or file data: all operational responses are proxied from Pterodactyl.

## Capability model

There are only `owner`, `admin`, and `manager` roles. Owners always act immediately. Admins receive only explicit role permissions. Managers need both an explicit server assignment and a feature permission; server-list filtering and direct detail route checks enforce this server-side. Permission precedence is deny, approval-required, allow, then role default. The migration creates permission/role/user overrides, assignments, approvals, notifications, sessions, encrypted connection storage, and indexed audit records.

The API separates Client endpoints (resources, power, files, backups, databases, schedules, startup, allocations) from Application endpoints (server discovery and administration). Expand the gateway’s endpoint mappings only with a documented Pterodactyl endpoint; do not pass application credentials to frontend code.

## Ubuntu 22.04 production deployment

### 1. Capacity, DNS, and base packages

Use a minimum 2 vCPU / 4 GB RAM / 40 GB SSD VPS; 4 vCPU / 8 GB is recommended for a busy team. Create an `A`/`AAAA` record such as `control.example.com` pointing to the VPS. Then:

```bash
sudo apt update && sudo apt -y upgrade
sudo apt install -y curl git build-essential nginx mariadb-server certbot python3-certbot-nginx ufw
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
```

### 2. MySQL/MariaDB

```bash
sudo mysql_secure_installation
sudo mysql
CREATE DATABASE sentinel CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'sentinel'@'127.0.0.1' IDENTIFIED BY 'use-a-long-unique-password';
GRANT ALL PRIVILEGES ON sentinel.* TO 'sentinel'@'127.0.0.1'; FLUSH PRIVILEGES;
EXIT;
```

### 3. Application install and configuration

```bash
sudo useradd --system --create-home --home-dir /opt/sentinel --shell /usr/sbin/nologin sentinel
sudo -u sentinel git clone <YOUR-REPOSITORY-URL> /opt/sentinel/app
cd /opt/sentinel/app
sudo -u sentinel npm ci --omit=dev
sudo -u sentinel cp .env.example .env
openssl rand -hex 48                 # SESSION_SECRET
openssl rand -base64 32              # ENCRYPTION_KEY
sudo -u sentinel editor .env
sudo -u sentinel npm run db:migrate
sudo -u sentinel npm run build
```

Set `HOST=127.0.0.1`, `PORT=7799`, a complete MySQL URL, the generated secrets, your HTTPS Pterodactyl URL, and least-privilege Pterodactyl application/client keys in `.env`. The Application key must never be added to browser configuration or Git. Create the initial owner through the owner CLI after provisioning it (or insert only an `scrypt` hash generated by the application); never share the bootstrap password. Configure connection settings as encrypted ciphertext via the protected owner settings workflow.

### 4. systemd (internal port 7799)

Create `/etc/systemd/system/sentinel.service`:

```ini
[Unit]
Description=Sentinel control panel
After=network.target mariadb.service
[Service]
Type=simple
User=sentinel
Group=sentinel
WorkingDirectory=/opt/sentinel/app
EnvironmentFile=/opt/sentinel/app/.env
ExecStart=/usr/bin/node /opt/sentinel/app/dist/server.js
Restart=on-failure
RestartSec=5
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ReadWritePaths=/opt/sentinel/app
[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R sentinel:sentinel /opt/sentinel/app
sudo chmod 640 /opt/sentinel/app/.env
sudo systemctl daemon-reload && sudo systemctl enable --now sentinel
sudo systemctl status sentinel
```

### 5. Nginx, domain, HTTPS, and firewall

Create `/etc/nginx/sites-available/sentinel` and replace the domain:

```nginx
server { listen 80; server_name control.example.com; return 301 https://$host$request_uri; }
server { listen 443 ssl http2; server_name control.example.com;
  client_max_body_size 250m;
  location / { proxy_pass http://127.0.0.1:7799; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto https; proxy_read_timeout 90s; }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/sentinel /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d control.example.com
sudo ufw allow OpenSSH && sudo ufw allow 'Nginx Full' && sudo ufw enable
```

Do **not** add a UFW rule for `7799`; it is loopback-only. Verify renewal with `sudo certbot renew --dry-run`.

### Operations, updates, backup, and restore

Logs: `sudo journalctl -u sentinel -f`; restart: `sudo systemctl restart sentinel`. Update with maintenance enabled: `sudo -u sentinel git -C /opt/sentinel/app pull`, `npm ci --omit=dev`, `npm run db:migrate`, `npm run build`, then restart. Back up: `mysqldump -u sentinel -p sentinel | gzip > sentinel-$(date +%F).sql.gz` and archive the encrypted `.env` separately. Restore only after stopping the service: `gunzip -c backup.sql.gz | mysql -u sentinel -p sentinel`; restore the application checkout and `.env`, then start it.

### Troubleshooting and security checklist

Check `curl -f http://127.0.0.1:7799/healthz`, systemd logs, Nginx error logs, DNS, and MariaDB credentials. For Pterodactyl errors confirm its URL/certificate/key and Wings connectivity. Before production: enforce HTTPS, preserve secret permissions, rotate keys, make database backups, restrict MySQL to localhost, set a long session secret, review Owner permissions/assignments, test manager IDOR denial, verify CSRF cookies, and keep OS/Node dependencies updated. Production error responses intentionally avoid stack traces and logs redact credentials.
